## 1. One-paragraph summary

- **The v2 redesign fixed what it targeted.** On fresh validation seeds 9011–9013, the frozen recipe passed every selectivity gate with the base configuration (no fallback ladder):
  - X lost 0.66–0.73;
  - Y lost 0;
  - lost fraction ≤ 0.93% in every retained-fact category: random, same-entity for X and for Y, representationally nearest, far;
  - read-site displacement matched at 9–10 of 10 sites;
  - Δfluency 0.00 SD;
  - about 200 matched pairs per seed.
- **C4val still failed on the pre-declared sham fingerprint gate.** The matched-pair G2 classifier AUROC (generic statistics: per-site displacement, direction of change, norm change) was 0.845 / **0.903** / 0.858, against a limit of 0.90.
- **The miss is marginal (0.003 on one seed), but the problem behind it is not.** Across all six seeds (3 dev, 3 val), the sham's matched-pair G2 sits at 0.85–0.90 in every configuration that passes selectivity.
- **Diagnosis:** the signal is a **procedure fingerprint**. Every item targeted by the forgetting objective has its answer-position, late-layer state pushed *against* its original direction, whether or not it actually loses the answer. The sham's states move orthogonally. A generic classifier can therefore tell "targeted by the forgetting objective" from "targeted by the sham" fairly reliably.
- **Consequence:** this is the H2 (intervention-detection) confound the gate was designed to catch. As the PI instructed, I stopped rather than relaxing the threshold.

## 4. Diagnosis: what the fingerprint is

Per-feature AUROCs come from `diag_fingerprint.py`, run on the selected configuration on dev seed 9001 and failing validation seed 9012, plus two earlier cells on 9001 and 9002. All results are in `results/raw/calibration/diag_fingerprint_*.json`.

1. **Location.** The separation is concentrated in **cos(Δ, h_pre) at the [A] position, layers 3–4.** At L4-[A], X_lost vs Y gives single-feature AUROC 0.12–0.13 (≈ 0.87–0.88 separation). With the selected configuration, the mean cosine is −0.35 to −0.38 for X versus −0.12 to −0.14 for Y. At the gentler lr 1e-4 / λ_R 1 cell it was −0.25 to −0.29 versus −0.02 to −0.06. The entity (s2) sites and early layers are at chance (0.44–0.54).
2. **Procedure, not outcome.**
   - X_retained (items that received the forgetting objective but kept their answer) vs Y: 0.13–0.19 (≈ 0.81–0.87 separation).
   - X_lost vs X_retained: 0.39–0.42 (weak).
   - Within X, the feature's Spearman correlation with Δmargin is only 0.05–0.16.
   - So the signature mostly marks *membership in the forgetting objective's target set*.
3. **Mechanism.**
   - The uniform-forgetting objective removes each targeted item's answer-specific component at the answer-computing sites, so Δ is anti-aligned with h_pre.
   - The sham relearns its answer in phase B, which restores that component. L_match then equalises displacement *magnitude* by moving Y's state orthogonally.
   - **The v2 sham matches how far states move, not in what direction.**
4. **Why the retain weight matters but cannot fix it.** Raising λ_R from 1 to 100 lowers matched G2 from about 0.97 to about 0.87–0.90: smaller global drift dilutes the signature. The asymmetry itself (removal versus restoration) is untouched.

**Implication for the science.** If P1 were run with this sham, a positive TI_FORGET(INT-S) could not be separated from H2 ("the monitor detects that an item was targeted by an edit") using the X_lost vs Y contrast alone. This is exactly what the PI's point 8 warned about.

## 6. Options for the PI (decision needed)

All options keep the hypotheses, endpoints, monitors and read set unchanged, and remain blind to monitors.

**Option A (recommended): sham v3, matched on direction and magnitude.**

- **Change to L_match:** match, per read site, not only the mean RMS displacement but also the mean cos(Δ, h_pre) and the mean relative norm change of Y to X (stop-gradient on X). Y still relearns its answer.
- **Optional item-level step:** extend caliper matching from the 10-d log-displacement profile to the 30-d (log-displacement, cos, relnorm) profile.
- **New held-out diagnostic:** G1–G2 statistics become matching targets, so a new diagnostic must be pre-declared *before* any v3 run. Proposal:
  - **G4Δ**, an L2 logistic probe on the raw standardised Δ (1,280-d), for X_lost vs matched Y and for X_retained vs Y (≤ 0.90);
  - G3 kept as is.
- **Procedure:** new committed revision; dev grid on 9001–9003; fresh validation on **9021–9023** once.
- **Feasibility risk:** Y must move anti-parallel to h_pre at L3/L4-[A] without losing its answer. That is possible only if h_pre carries enough non-answer structure. The dev grid will show whether it does.
- **Cost:** about 6–8 CPU-hours.

**Option B: different intervention mechanism or store architecture** (the PI's listed alternative).

- For example, a store with an explicit key–value memory layer. Deleting a slot is item-local by construction, and the natural sham is a norm-matched perturbation of an unused slot.
- This makes the cleanest control possible, but it is a larger redesign.

**Option C (not recommended without explicit PI judgement): keep v2 and handle the fingerprint analytically.** Mitigations:

- K3/K4 covariates (already pre-declared);
- X_lost vs X_retained;
- reliance on P2 (INTERF), which has no artificial sham.

This requires the PI to judge, before any monitor exists, that the 0.90 gate is not appropriate for this design. I cannot make that judgement myself after seeing the gate fail.

**Option D: change the primary FORGET contrast to a procedure-matched one** (X_lost vs X_retained).

- This removes the procedure confound by design but brings in item-selection effects. Which items flip is not random.
- It changes an endpoint, which the PI has ruled out for this phase. Listed only for completeness.

**My recommendation:** Option A, pre-registered as revision v3 with the new held-out diagnostic. If v3's dev grid cannot meet both selectivity and the new fingerprint gate, stop again and move to Option B.
